# bazis-test-utils 2.5.2

## Changes

- **The schedules of bazis-bg.** `apply_declarations()` and the fixture `bazis_declared`
  also apply the periodic tasks declared in the `schedules.py` modules (bazis-bg 2.6,
  `bazis.contrib.bg.declare`), as `migrate` does; an older bazis-bg without them is
  skipped.
- **The throttles start from zero in each test.** The counts of the request rate limits of
  Bazis are kept in Redis, also between the runs, so a test could get the 429 of the tests
  run before it. The plugin calls `throttle_reset()` of the core (Bazis 2.16) before each
  test, when `bazis.core` is installed; within a test the throttles count as usual. The
  fixtures of the projects that deleted the keys `bazis:throttle:*` are no longer needed.
- **`parallel()`: requests at once.** `bazis_test_utils.utils.parallel(count, func)` and
  `parallel([f1, f2, ...])` run the calls in threads started together (a barrier) and
  return their results in the order of the calls; each thread closes its database
  connections when its call is done, and the first exception of a call is raised in the
  test. For the tests of the invariants under concurrent requests (the README, "Parallel
  requests"); it replaces the local helpers of the test suites.
